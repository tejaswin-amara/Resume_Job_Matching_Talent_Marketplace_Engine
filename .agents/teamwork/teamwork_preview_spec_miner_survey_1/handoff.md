## 2. Logic Chain

From the direct observations, the following system requirements and technical dependencies logically follow:

1. **Embedding & Vector Storage (pgvector)**:
   - Cosine distance in PostgreSQL pgvector is calculated via the `<=>` operator (cosine distance = $1 - \text{cosine similarity}$).
   - Therefore, cosine similarity between vectors $\vec{u}$ and $\vec{v}$ is $1 - (\vec{u} \Leftrightarrow \vec{v})$.
   - The sentence transformer model (e.g. `sentence-transformers/all-MiniLM-L6-v2`) produces 384-dimensional dense vectors.
   - Vectors must be normalized or raw, with similarity bounded within $[0, 1]$.

2. **Scoring Mathematical Formulation**:
   - The formula `total = 100 * (0.40 * semantic + 0.35 * skill + 0.15 * experience + 0.10 * education)` mandates that each individual signal is strictly bounded to the interval $[0.0, 1.0]$.
   - Each signal requires dedicated zero-division safeguards:
     - If $|J_{skills}| = 0$, $S_{skill} = 1.0$ (no requirements violated).
     - If $E_{req} \le 0$, $S_{experience} = 1.0$ (no minimum experience demanded).
     - If $Rank_{req} = 0$, $S_{education} = 1.0$ (no specific degree required).
     - If vector norms are 0 or empty text, $S_{semantic} = 0.0$.

3. **Data Integrity & Alembic Migrations**:
   - PostgreSQL tables must include pgvector extension activation: `CREATE EXTENSION IF NOT EXISTS vector;`.

## 3. Comprehensive Specifications

### 3.1 Mathematical Formulas & Calibration Logic for Hybrid ATS Score

The ATS Engine computes a composite score $T \in [0.0, 100.0]$:

$$T = 100.0 \times \left(0.40 \cdot S_{\text{semantic}} + 0.35 \cdot S_{\text{skill}} + 0.15 \cdot S_{\text{experience}} + 0.10 \cdot S_{\text{education}}\right)$$

#### Signal 1: Semantic Similarity ($S_{\text{semantic}} \in [0.0, 1.0]$, Weight = 40%)
- **Input**: Resume text embedding vector $\vec{u} \in \mathbb{R}^d$, Job description embedding vector $\vec{v} \in \mathbb{R}^d$ ($d=384$).
- **Raw Cosine Similarity**:
  $$\cos(\vec{u}, \vec{v}) = \frac{\vec{u} \cdot \vec{v}}{\|\vec{u}\|_2 \|\vec{v}\|_2}$$
- **Zero-Division & Degeneracy Protection**:
  $$\text{If } \|\vec{u}\|_2 == 0 \text{ or } \|\vec{v}\|_2 == 0 \implies \cos(\vec{u}, \vec{v}) = 0.0$$
- **Calibration / Normalization**:
  Cosine similarity for dense text embeddings can range from $[-1.0, 1.0]$, but semantic relevance is non-negative:
  $$S_{\text{semantic}} = \max\left(0.0, \min\left(1.0, \cos(\vec{u}, \vec{v})\right)\right)$$
  *(Alternatively, linear normalization $S_{\text{semantic}} = \frac{\cos(\vec{u}, \vec{v}) + 1.0}{2.0}$ can be configured, but standard clipped cosine ensures orthogonal/irrelevant text yields 0).*

#### Signal 2: Skill Match ($S_{\text{skill}} \in [0.0, 1.0]$, Weight = 35%)
- **Input**:
  - Candidate extracted skills: $C = \{s_1, s_2, \dots, s_m\}$ (canonicalized to lowercase taxonomy).
  - Job required skills: $R = \{r_1, r_2, \dots, r_k\}$.
  - Job preferred skills: $P = \{p_1, p_2, \dots, p_j\}$.
  - Total job target skills: $J = R \cup P$.
- **Matched & Missing Sets**:
  $$M = C \cap J \quad (\text{Matched Skills})$$
  $$Missing = J \setminus C \quad (\text{Missing Skills})$$
- **Calibration Formula**:
  - If $|J| == 0$ (job requires no specific skills):
    $$S_{\text{skill}} = 1.0$$
  - If $|J| > 0$ and $P = \emptyset$ (only required skills):
    $$S_{\text{skill}} = \frac{|C \cap R|}{|R|}$$
  - If both Required ($R$) and Preferred ($P$) are specified ($|R| > 0$ and $|P| > 0$):
    Weighted combination (80% required coverage + 20% preferred coverage):
    $$S_{\text{skill}} = 0.80 \times \left(\frac{|C \cap R|}{|R|}\right) + 0.20 \times \left(\frac{|C \cap P|}{|P|}\right)$$
  - Bound: $S_{\text{skill}} = \max\left(0.0, \min\left(1.0, S_{\text{skill}}\right)\right)$.
  - Empty Candidate Skills: If $C = \emptyset$ and $|J| > 0 \implies S_{\text{skill}} = 0.0$.

#### Signal 3: Experience Alignment ($S_{\text{experience}} \in [0.0, 1.0]$, Weight = 15%)
- **Input**:
  - Candidate verified experience in years: $E_{\text{cand}} \ge 0.0$.
  - Job required experience in years: $E_{\text{req}} \ge 0.0$.
- **Calibration Formula**:
  - If $E_{\text{req}} \le 0.0$:
    $$S_{\text{experience}} = 1.0$$
  - If $E_{\text{req}} > 0.0$:
    - When $E_{\text{cand}} \ge E_{\text{req}}$:
      Candidate satisfies experience requirement fully:
      $$S_{\text{experience}} = 1.0$$
      *(No penalty for overqualification up to $3\times E_{\text{req}}$, ensuring top talent is not penalized).*
    - When $E_{\text{cand}} < E_{\text{req}}$:
      Proportional partial credit:
      $$S_{\text{experience}} = \frac{E_{\text{cand}}}{E_{\text{req}}}$$
  - Bound:
    $$S_{\text{experience}} = \max\left(0.0, \min\left(1.0, S_{\text{experience}}\right)\right)$$
- **Zero-Division Safeguard**:
  $$S_{\text{experience}} = 1.0 \quad \text{whenever } E_{\text{req}} \le 0.0$$

#### Signal 4: Education Fit ($S_{\text{education}} \in [0.0, 1.0]$, Weight = 10%)
- **Education Ordinal Hierarchy**:
  | Degree Level | Canonical Name | Ordinal Rank ($R$) |
  |---|---|---|
  | None / Unspecified | `none` | 0 |
  | High School / GED | `high_school` | 1 |
  | Associate Degree | `associate` | 2 |
  | Bachelor's Degree | `bachelor` | 3 |
  | Master's Degree | `master` | 4 |
  | Doctorate / Ph.D. / Professional (MD, JD) | `doctorate` | 5 |
- **Calibration Formula**:
  - Let $R_{\text{cand}} \in \{0, 1, 2, 3, 4, 5\}$ and $R_{\text{req}} \in \{0, 1, 2, 3, 4, 5\}$.
  - If $R_{\text{req}} == 0$ (no degree requirement specified):
    $$S_{\text{education}} = 1.0$$
  - If $R_{\text{cand}} \ge R_{\text{req}}$:
    Candidate meets or exceeds education credential:
    $$S_{\text{education}} = 1.0$$
  - If $R_{\text{cand}} < R_{\text{req}}$:
    Normalized ratio step credit:
    $$S_{\text{education}} = \frac{R_{\text{cand}}}{R_{\text{req}}}$$
  - Bound:
    $$S_{\text{education}} = \max\left(0.0, \min\left(1.0, S_{\text{education}}\right)\right)$$
- **Zero-Division Safeguard**:
  $$S_{\text{education}} = 1.0 \quad \text{whenever } R_{\text{req}} == 0$$

## 6. Full API Endpoint Contracts & Schemas

All error responses adhere to **RFC 7807 Problem Details** (`application/problem+json`).

### 6.1 Standard RFC 7807 Error Response Schema
```json
{
  "type": "https://errors.talentmarketplace.dev/validation-error",
  "title": "Validation Error",
  "status": 422,
  "detail": "Field 'title' is required and cannot be empty.",
  "instance": "/api/v1/jobs"
}
```

### 6.2 Endpoint 1: Resume Upload & Parsing
- **Method**: `POST`
- **Path**: `/api/v1/resumes/upload`
- **Content-Type**: `multipart/form-data`
- **Request Parameters**:
  - `file`: Binary file (PDF, DOCX, or TXT, max 10MB)
  - `candidate_name` *(optional string)*: Candidate name override
  - `candidate_email` *(optional string)*: Candidate email override
- **Response Status**: `200 OK` or `201 Created`
- **Response Body**:
```json
{
  "candidate_id": 101,
  "resume_id": 204,
  "filename": "john_doe_resume.pdf",
  "parsed_data": {
    "contact_info": {
      "name": "John Doe",
      "email": "john.doe@example.com",
      "phone": "+1-555-0199",
      "location": "San Francisco, CA",
      "linkedin": "https://linkedin.com/in/johndoe",
      "github": "https://github.com/johndoe"
    },
    "skills": ["Python", "FastAPI", "PostgreSQL", "Docker", "React"],
    "experience_years": 4.5,
    "education_level": "bachelor",
    "education_details": [
      {
        "degree": "Bachelor of Science in Computer Science",
        "institution": "University of California, Berkeley",
        "year": 2021
      }
    ],
    "raw_text_snippet": "Senior Software Engineer with 4+ years of experience in Python and FastAPI..."
  },
  "created_at": "2026-09-29T13:45:00Z"
}
```
- **Error Responses**:
  - `400 Bad Request`: File empty or exceeds size limit.
  - `415 Unsupported Media Type`: File is not PDF, DOCX, or text/plain.

## 7. ATS Explainability Specification & Output Schema

The ATS explainability engine translates numerical matching tensors into human-auditable talent insights:

1. **`matched_skills`**:
   - Exact intersection between candidate skills and job target skills ($C \cap J$).
   - Rendered as green badges in frontend UI.
2. **`missing_skills`**:
   - Set difference ($J \setminus C$), segmented into **Missing Required** (critical gaps, red badges) and **Missing Preferred** (bonus gaps, yellow badges).
3. **`score_breakdown`**:
   - 4-tuple providing per-signal transparency:
     - `raw_score`: float in $[0.0, 1.0]$
     - `weight`: float percentage ($0.40, 0.35, 0.15, 0.10$)
     - `weighted_score`: float in $[0.0, 40.0]$, etc.
     - Contextual metadata (e.g. candidate vs required years, candidate vs required degree).
4. **`improvement_suggestions`**:
   - Algorithmic advice generated based on deficit signals:
     - If $S_{\text{experience}} < 0.80$: Suggests emphasizing project complexity or leadership to compensate for tenure delta.
     - If missing required skills exist: Identifies top 2 highest-value skills to acquire.
     - If $S_{\text{semantic}} < 0.60$: Suggests tailoring resume terminology to mirror the requisition vocabulary.

## 8. Caveats

- **Embedding Model Weight Loading in CI / Test Environments**: Loading a 384d sentence transformer model (e.g. `all-MiniLM-L6-v2`) requires internet access on first run to download model weights or an offline fixture. For unit tests, a deterministic mock or lightweight embedder fixture should be provided so tests run rapidly and deterministically without network dependencies.
- **pgvector Extension Requirement**: PostgreSQL must have `pgvector` compiled and loaded. In Docker Compose, the official image `pgvector/pgvector:pg16` is required.
- **Skill Extraction Scope**: Production ATS parsers range from keyword taxonomy matching to zero-shot LLM entity extraction. The baseline requirement specifies a robust curated taxonomy + regex/token matching with alias resolution, ensuring instant deterministic results and high testability.
